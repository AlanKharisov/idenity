# RECAP: 2026-05-24 Backend Deployment & Collection Minting Fixes

## Що було зроблено

1. **Відновлення доступу та деплой бекенду (Idenity API)**
   - З'ясували, що справжній сервер Idenity знаходиться на `13.48.84.220` (до якого прив'язаний `idenity-backend.duckdns.org`), а не на `51.20.191.109` (там працює CalorieSnap).
   - Через AWS EC2 Instance Connect додали мій SSH ключ (`id_ed25519.pub`) до `ubuntu`.
   - Закинули оновлений код з папки `api/` на сервер.
   - Скомпілювали Rust бекенд (`cargo build --release`), виправили порт у `.env` на `8081` (щоб він збігався з налаштуваннями Caddy) та успішно перезапустили сервіс.
   - **Результат:** CORS помилки повністю зникли, а ендпоінт AI генерації `/api/ai/generate` тепер доступний і успішно повертає зображення.

2. **Фікс Phantom Wallet та створення колекцій**
   - Виправили баг із `Blockhash not found`, який виникав через розсинхронізацію Solana Devnet RPC під час підтвердження кожного фото окремо.
   - **Рефакторинг мінта колекцій:** Тепер усі NFT в колекції збираються в один масив транзакцій і підписуються **за один клік** за допомогою `signAllTransactions`. Це не тільки вирішило проблему з помилками блокчешу, але й зробило UX набагато кращим (Phantom з'являється лише один раз).
   - Додали параметр `{ skipPreflight: true }` для надійнішої відправки транзакцій на devnet.

3. **Деплой фронтенду (GitHub Pages)**
   - Усі останні зміни у фронтенді (папка `identity/`) були закомічені та запушені у гілку `master` на GitHub.
   - Було виконано команду `npm run deploy`, яка успішно зібрала React додаток і запушила оптимізований білд у гілку `gh-pages`.
   - **Результат:** Додаток тепер публічно доступний через GitHub Pages і автоматично стукає на віддалений бекенд `idenity-backend.duckdns.org`.

## Важливі нотатки
- Якщо Phantom коли-небудь знову видаватиме `Receiving end does not exist`, це внутрішній баг Firefox/розширення, і лікується рестартом розширення в `about:addons`.
- Оскільки фронтенд використовує `BrowserRouter`, при прямому переході за посиланням (або оновленні сторінки F5) на внутрішніх сторінках у GitHub Pages може бути помилка 404 (це відома особливість GH Pages для SPA додатків). Починати роботу краще з головної сторінки.
