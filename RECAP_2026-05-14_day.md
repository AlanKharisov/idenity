# Recap — 2026-05-14 — Day summary: Moderation + Business panels

## TL;DR
Сегодня закрыли две большие дыры в продукте: появился **админ-инструмент** для ручной модерации компаний и **бизнес-панель** для самих компаний после апрува. Эти два веб-приложения вместе закрывают цикл «компания подала заявку → админ одобрил → компания работает с CRM из браузера».

## What shipped

### 1. Backend moderation API (`api/`)
- Новый модуль `handlers/admin.rs` с CRUD-эндпоинтами модерации компаний: `GET /api/admin/companies?status=...`, `POST .../approve|reject|ban|unban`.
- Чек админа через `ADMIN_UIDS` env (comma-separated Firebase UIDs) — без миграций и Firestore-флагов.
- Расширил `UserData`: `banned`, `companyName`, `registrationNumber`, `contactEmail`, `businessDescription`, `approvalRequestedAt`, `reviewedAt/By`, `approvalStatus`, `rejectionReason`, `banReason`.
- Чинил `request-approval` — раньше **автоапрувил** мгновенно, теперь сохраняет заявку и ставит `pendingApproval=true`.
- Детали: см. [[RECAP_2026-05-14_admin_panel]]

### 2. Admin panel (`admin/`)
- Отдельный Vite+React+TS веб (порт 3001). Тёмная тема в духе Marki.
- Login через Google или email/password (один Firebase-проект `idenity-e7f29`).
- 5 табов: Pending / Approved / Rejected / Banned / All.
- Карточка компании с full аудит-данными + кнопки Approve / Reject / Ban / Unban.
- Reject — причина опциональна; Ban — обязательна; Ban запрещён на самого себя.
- Детали: см. [[RECAP_2026-05-14_admin_panel]]

### 3. Business panel (`admin-company/`)
- Vite+React+TS веб (порт 3002), responsive: sidebar на ПК, bottom-nav на мобиле.
- Access-gate автоматический: `companyApproved=true` || одна из ролей (`owner/manager/controller/courier`). Banned → терминальный экран.
- Если юзер залогинен но не апрувнут — может подать заявку прямо из веба, без возврата в мобильную апку.
- 8 страниц: Dashboard, CRM (orders/deliveries/NFC), NFTs (single create), Marketplace, Feed, Wallets (Marki + crypto), Notifications, Profile.
- Solana on-chain mint (batch/editions) — открытый TODO; пока flow живёт в мобильной апке.
- Детали: см. [[RECAP_2026-05-14_admin_company]]

## How the three pieces fit together

```
mobile identity app          admin web                    admin-company web
─────────────────────        ──────────                   ─────────────────────
ProfilePage → submit  ──▶  Pending list ─── Approve ──▶  AccessDenied resolves
"company verification"     (you)            sets         → full CRM unlocks
                                            companyApproved
```

Цикл закрыт: компания может пройти весь путь от регистрации до полноценной работы без участия человека (кроме клика «Approve» в админке).

## Operational notes

- Бэк должен запускаться **из `api/`** (`cd api && cargo run -p idenity-api`) — `dotenvy` ищет `.env` по cwd и выше.
- Локальные dev-фронты: `cd admin && npm run dev` (порт 3001), `cd admin-company && npm run dev` (порт 3002).
- Прод-деплой: для каждого фронта build → static `dist/`, выставить `VITE_API_URL=https://idenity-backend.duckdns.org`. Для бэка — пересобрать `cargo build --release` и обновить env на сервере (особенно `ADMIN_UIDS`).
